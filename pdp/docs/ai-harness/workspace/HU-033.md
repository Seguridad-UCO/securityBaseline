# HU-033 — `MFA_REQUIRED` responde `403`, no `400`

> Nueva (2026-10-28). Surge de la validación de Edge de HU-027: `GET /api/v1/applications/{id}/administrators` respondía
> `400 MFA_REQUIRED` a un administrador autenticado sin evidencia de MFA.
> **Depende de:** HU-024 (MFA step-up). **Contrato afectado:** estado HTTP de un código de error ya existente.

## Por qué existe esta historia

`MfaEvidenceRequiredException` es una `BusinessRuleViolationException`. `ApiErrorHandler` mapea toda regla de negocio a `400`
salvo `ConflictBusinessRuleException` (409) y dos códigos explícitos (`NOT_AUTHORIZED_TO_ADMINISTER`,
`CURRENT_USER_APPLICATIONS_ACCESS_DENIED`) que dan `403`. `MFA_REQUIRED` cae en el `400` por omisión.

Pero `400` significa "petición mal formada", y aquí la petición es válida: falta **contexto de autenticación suficiente**.
ADR-031 lo dice expresamente: si el host no eleva el token, "esas operaciones reciben 403 — es el comportamiento
correcto". ADR-014 reserva `403` para "autenticado pero no autorizado". El código contradice la ADR.

## Enunciado

> Como **cliente de la API de administración**, quiero **que la falta de evidencia de MFA se responda con `403` y el
> código `MFA_REQUIRED`**, para distinguirla de un error de validación de mi petición y reaccionar pidiendo un step-up.

## Lo que ya está decidido (no reabrir)

| Pregunta | Decisión | De dónde sale |
|---|---|---|
| ¿Qué estado HTTP? | `403` | ADR-031, ADR-014 |
| ¿Cambia el `code`? | No: sigue siendo `MFA_REQUIRED` | HU-024 |
| ¿Se toca la lógica de MFA o su configuración? | No | ADR-027 |
| ¿Dónde se mapea? | En el `ApiErrorHandler` único (no un handler nuevo) | CLAUDE.md |
| ¿Algún consumidor depende del `400`? | Ninguno: `securityBaseline-vue` y `security-ui` no referencian `MFA_REQUIRED` | grep 2026-10-28 |

## Alcance

**Cubre:** el mapeo en `ApiErrorHandler` y su prueba; la nota de contrato en `HU-024`/`HU-027` si lo citan.
**No cubre:** la política de MFA, el realm de Keycloak, `WWW-Authenticate` con `insufficient_user_authentication` (RFC 9470),
que queda como mejora si algún host lo necesita.

## Criterios de aceptación

1. Una operación administrativa sin evidencia de MFA responde `403` con `code=MFA_REQUIRED` y el sobre `ProblemDetail`.
2. Un error de validación de la petición sigue respondiendo `400`; un conflicto, `409`.
3. `verificar.ps1` completo, `consistencia.ps1` y `drift.ps1` en verde.
